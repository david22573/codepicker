### **Phase 1: The "Brain" Upgrade (Protocol Optimization)**

*Goal: Drastically increase reliability and reduce "hallucinations" without changing the model.*

**1.1 Implement Prefill Injection (High Priority)**

* **Concept:** Don't wait for the model to decide how to format output. Force it.
* **Action:** Modify your OpenRouter client to append a partial "Assistant" message at the very end of your message history.
* **Implementation:**
In `internal/llm/openrouter.go` (or wherever you build the request), check if `Prefill` is set in your config.

```go
// Example Modification to your ChatCompletionRequest builder
func (c *Client) CreateChatCompletion(ctx context.Context, req *ChatCompletionRequest) (*ChatCompletionResponse, error) {
    
    // ... existing setup ...

    // TRICK: Inject the start of the JSON to force structured output
    // This "hypnotizes" the model into compliance immediately.
    if req.Prefill != "" {
        req.Messages = append(req.Messages, Message{
            Role:    "assistant",
            Content: req.Prefill, // e.g., "{\"thought\": \""
        })
    }

    // ... send request ...
}

```

* **Usage:** When asking for a file edit, prefill with: `{"file": "main.go", "action": "rewrite", "code": "`

**1.2 Grammar/Schema Enforcement**

* **Concept:** Stop parsing errors before they happen.
* **Action:** For DeepSeek V3 (via OpenRouter), enable "JSON Output" mode where possible, or use the "Prefill" strategy above to simulate it.
* **Impact:** Zero tokens wasted on "Here is the code..." chatter.

### **Phase 2: The "Context" Upgrade (Input Optimization)**

*Goal: Fit 5x more codebase knowledge into the same context window.*

**2.1 Code Skeletonization**

* **Concept:** The "Architect" agent doesn't need to see the inside of every function to plan a refactor; it just needs signatures.
* **Action:** Implement a `Skeletonize` tool using a lightweight parser (standard regex or `go/parser`).
* **Logic:**
1. Read file.
2. Keep package declarations, imports, struct definitions, and func signatures.
3. Replace func bodies with `// ... (implementation hidden)`.
4. Feed this "Skeleton Map" to the Supervisor/Planner agent.


* **Impact:** You can now load the entire project structure into context, not just 2-3 files.

### **Phase 3: The "Body" Upgrade (Interactive UI)**

*Goal: Move from "Batch CLI" to "Interactive Console".*

**3.1 Bubble Tea Interface**

* **Concept:** Replace `ui/console` with `charmbracelet/bubbletea`.
* **Action:** Build a "Review TUI" for the shadow filesystem.
* **View 1 (Diff):** Split pane showing `Shadow` vs `Actual`.
* **Controls:** `Space` to stage, `Enter` to apply, `d` to discard.


* **Library:** `github.com/charmbracelet/bubbletea` + `github.com/charmbracelet/lipgloss` (for styling).

**3.2 Streaming Markdown Renderer**

* **Concept:** Render the LLM's thought process in real-time with syntax highlighting.
* **Action:** Pipe the `ChatCompletionStream` output into `charmbracelet/glamour`.

### **Phase 4: The "Ecosystem" Upgrade (Connectivity)**

*Goal: Stop writing custom tools. Use everyone else's.*

**4.1 Generic MCP Client**

* **Concept:** Support the "Model Context Protocol" to use standard Claude tools.
* **Action:** Implement an MCP Client in Go.
* **Library:** `github.com/mark3labs/mcp-go`
* **Config:**
```yaml
# .codepicker/config.yaml
mcp_servers:
  - name: github
    command: npx
    args: ["-y", "@modelcontextprotocol/server-github"]

```


* **Impact:** `codepicker` instantly gains the ability to read GitHub issues, query Postgres, or check Sentry logs without you writing any new Go code.

---

### **Phase 5: The "Workflow" Upgrade (Agents & Safety)**

*Goal: Automate the "Thinking" process.*

**5.1 The "Planner" Command**

* **Concept:** `codepicker plan <request>`
* **Flow:**
1. **Skeletonize:** Load project map.
2. **Architect Agent:** Reviews map + request.
3. **Output:** Generates/Updates `ARCHITECTURE_GOALS.md`.
4. **User Review:** You verify the plan before any code is touched.



**5.2 Middleware Hooks**

* **Concept:** "Guard Rails" for your tools.
* **Action:** Define a `ToolMiddleware` interface.
```go
type ToolMiddleware interface {
    BeforeExecute(toolName string, args map[string]interface{}) error
}

```


* **Use Case:** Block `rm -rf`, prevent editing `go.mod` without explicit flag, or run `go fmt` automatically after every `WriteFile`.
